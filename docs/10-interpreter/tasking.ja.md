# マルチタスクとタスク切り替え：3 本のリストと 1 つの手口

[English](tasking.en.md) ｜ **日本語** ｜ [繁體中文](tasking.md)

UCSD Pascal には `PROCESS`、`START`、`SEMAPHORE` がある——1978 年の機械に本物の
並行性が載っていた。この稿では 8086 版がそれをどう実現しているかを見る。

結論から言うと、**触っているのはデータ・セグメント内の 3 本のリストだけ**であり、
切り替えの瞬間には乱暴に見えて判定を丸ごと省く手口が使われている——
**ディスパッチ表を全部同じアドレスで埋める**というものだ。

> 関連：[インタプリタの状態](machine-state.ja.md)｜
> [命令フェッチとディスパッチ](dispatch-and-threading.ja.md)

## 3 本のリスト

| 位置 | 何か |
|---|---|
| `ss:38h` | ready queue の先頭。**走っているタスクも入ったままで、しかも先頭にいる** |
| `ss:3Ch` | 現在のタスク（その TIB を指す） |
| セマフォ `+2` | そのセマフォを待つ TIB のリスト |

リストの「次」は TIB の `+0`、優先度は `+2` の**下位バイト**にある
（上位バイトはフラグ。@0x17C4 の `mov al,[bx+2]` は 1 バイトしか取らない）。

その他に使われる TIB のフィールド：

| オフセット | 何か |
|---|---|
| `+08` | SP |
| `+0A` | MP |
| `+0E` | IPC |
| `+10` | E_Rec |
| `+12` | MSPROC ＋ `ss:0E6h`（上位バイト） |
| `+14` | 待っているセマフォ。待っていなければ 0 |

## セマフォ

セマフォは 2 ワード——カウントと待ち行列の先頭。

**`WAIT`（@0x1755）**：カウントが 0 でなければ 1 減らして帰る。0 なら自分を
ready queue から外し（@0x1722）、優先度順にセマフォの待ち行列へ挿入し（@0x16E9）、
`TIB+14h` に待っているセマフォを記録して、切り替える。

**`SIGNAL`（@0x17D5 → ヘルパ @0x1791）**：カウントが負か、誰も待っていなければ
1 増やして帰る。待っている者がいれば行列の先頭を起こし、その `+14h` を消し、
優先度順に ready queue へ入れ、**起こした側の優先度が自分より低くない場合にだけ切り替える**
（@0x17C7 の `jb`）。

行列に入れるルーチン（@0x16E9）は、自分より優先度が**低い**最初の項目の手前で止まる——
同じ優先度は後ろに並ぶので、先に待った者が先に起こされる。

## 切り替えの手口

タスク切り替えは命令の途中では起こせない。オリジナルは「いま切り替えてよいか」を
判定する代わりに、**ディスパッチ表の 256 枠すべてを同じアドレスで埋める**：

```
18a6: push es; push di; push cx
18a9: xor di,di
18ac: push cs; pop es
18ae: mov cx, 0x100
18b1: rep stosw          ; 256 ワードすべてを ax にする
```

これで**次の命令が何であれ、そのアドレスに落ちる**。切り替えが済んだら表を書き戻す
（@0x1892、`0x1D56` から 512 バイトをオフセット 0 へ）。

落下点は @0x17E8：

```
17e8: dec si             ; lodsb が既に取ったバイトを返す
17e9: call 0x15F5        ; 状態一式を現在の TIB へ保存
17ec: call 0x1892        ; ディスパッチ表を書き戻す
17ef: bp = ss:34h; call 0x10F5   ; 現在セグメントの activity を 1 回数える
17f7: call 0x1837        ; 割り込み禁止
17fa: bp = ss:38h        ; ready queue の先頭
17ff: ss:3Ch = bp        ;   それが現在のタスクになる
1804: call 0x1623        ; 新しい TIB から状態一式を読み戻す
1807: call 0x183c        ; 割り込み許可
180a: 新セグメントは常駐しているか。していなければ segment fault
```

あの `dec si` がこの手口の代償だ。罠が効くのは `lodsb` の**あと**なので、
そのバイトを吐き戻す必要がある。

**この手口が記憶に値するのは、それが何を回避しているかにある。** 「いま切り替えてよいか」は
命令ごとに一度ずつ問わねばならない質問だが、「次のフェッチが自分から罠に落ちる」形に
変えれば一度も問わずに済む。代償は切り替えの瞬間に 512 バイトを 2 回動かすこと——
切り替えはもともと稀なので、この取引は割に合う。

一命令ずつ進む再実装機にこの手口は要らない。命令の末尾で切り替えれば同じことだからだ。
だが**この手口を知らないと、あの `dec si` はバグに見える。**

## 保存と復元

`@0x15F5` は保存する：`[TIB+8]=SP`、`+0A=MP`、`+0E=IPC`、`+10=E_Rec`、
`+12=MSPROC|ss:0E6h<<8`。

`@0x1623` はまず `MSPROC`、次に `E_Rec`（これに伴って `Env_Data`、`E_Vec`、`SIB`、
コード・セグメント値、手続き辞書、byte sex、定数プールが一式入れ替わる）、
最後に `IPC`、`MP`、`SP` を復元する。**セグメントが常駐しているかは検査しない**——
それは呼び出し側の仕事だ（@0x180A）。

`SPR`（プロセッサ・レジスタ書き込み）も同じ道を通る。TIB へ保存し、その枠を書き、
状態一式を読み戻す。書く相手がレジスタ −1（`ss:3Ch`）なら、その一歩がタスク切り替えそのものになる。

## 境界

- ready queue の挿入と削除、セマフォの 2 経路、切り替えの一連は全て一命令ずつ読み、
  [自己起動](../30-remake/specs/03-boot.ja.md)で実際に走らせている。
- 割り込み側は `ATTACH`（セマフォを `ss:4Eh` のベクタ表に繋ぐ）と @0x1878 の
  ディスパッチしか読んでいない。実際の割り込み源は追っていない。
- `TIB+04`／`+06`（スタックの上下限）は bootstrap が埋めるが、その算出方法は未解。
