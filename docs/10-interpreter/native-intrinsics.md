# 段 1 的內嵌原生程序：p-code 與機器碼的交界

作業系統本體是 p-code 寫的，但它總得有辦法搬記憶體、碰磁碟、關中斷。
IV.0 手冊 p.66 只說了一句：segment 1 的程序碼**可能**直接做在直譯器裡。
這一篇把那句話拆開——**那是這台機器上「哪些事不是 p-code」的完整清單**。

> 延伸閱讀：[段的切換](segment-switching.md)｜[直譯器的狀態](machine-state.md)｜
> [`SYSTEM.PME.86` 的檔頭](../20-formats/pme86-header.md)

## 界線是直譯器自己畫的

跨段呼叫進段 1 時，`CXG` 先查一張表（@0x13F4，`SCXG1` 走同一條）：

```
13f4: cmp bp, 1            ; 段號是 1 嗎
13f7: jnz 一般路徑
13f9: mov di, [si]         ; 偷看程序號（不前進）
13fb: and di, 0FFh
13ff: cmp di, 2Fh
1402: jg  一般路徑         ; > 47 → 沒有內嵌實作
1404: shl di, 1
1406: mov di, cs:[di+1F56h]
140b: cmp di, 0
140e: jz  一般路徑         ; 這一格是 0 → 沒有內嵌實作
1410: inc si
1411: jmp di               ; 直接跳進機器碼
```

`0x1F56` 起 48 格，以程序號為索引。**非零的有 33 格，相異的位址 26 個**
（七對指到同一支）。查不到就退回一般的跨段呼叫，去段 1 裡找 p-code。

所以這張表就是界線：**表上有的是宿主的事，其餘都是 p-code。**

## 26 支各是什麼

## 裝置那一族其實是同一支

18／19／31／33／34／36 全部落到同一段碼，只差一個寫進 `0x2AA0` 的模式碼：

| 模式 | 誰 |
|---:|---|
| 1 | `UNITREAD` |
| 2 | `UNITWRITE` |
| 3 | 程序 31／33 |
| 4 | 等裝置做完 |
| 8 | 問裝置狀態 |

參數塊在直譯器映像的 `0x2AA0`–`0x2AA8`：模式、unit、緩衝區位址、長度、
塊號、mode。堆疊上由頂往下推的次序是
`mode、block、length、緩衝區的（基底, 偏移）、unit`——
也就是 Pascal 的 `UNITREAD(unit, buf, length, block, mode)` 由左往右推。

做完把結果寫進 `IORESULT`（`ss:0E6h`，@0x2B3B 一進去就清成 0）。

## 兩個會咬人的細節

**`ss:0E6h` 一格兩用。** 它同時是 `IORESULT` 與 `MSPROC` 的高位元組
（@0x160F 存 task 狀態時把它併進 `TIB+12h`）。所以直譯器的狀態只有在
換 task 時才寫那一格——每次呼叫都寫會把裝置的結果蓋掉。

**做完之後不一定回到程序號後面。** `SCXG` @0x0545 一進來就把 `si` 存進
`ss:24h`，那時它指著**程序號**；@0x1410 的 `inc si` 之後才跳進機器碼。
多數原生程序自己會再存一次（`MOVELEFT` 在 @0x192C），所以還原到的是
程序號後面；**沒有自己存的那幾支還原到的就是程序號本身**，
而那個位元組會被當成下一條指令執行。程序 4 的號碼是 `04`，剛好是 `SLDC 4`。

## 邊界

- 「33 格非零、26 個相異位址」是直接讀映像位元組數出來的，可靠。
- 表上「做什麼」那一欄，有標「讀過」的是逐條讀完碼加上實際對拍驗過；
  沒標的只知道它在表上。
- 參數次序全部由 `pop` 順序讀出來，並且在
  [自舉](../30-remake/specs/03-boot.md)裡逐條與原版對拍過。
