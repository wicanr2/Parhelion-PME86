# 直譯器的狀態：四個暫存器加十幾個變數

p-machine 是一台堆疊機，手冊 p.13 列的暫存器有 `SP`、`MP`、`BASE`、`IPC`、`SEG`、
`JTAB`、`NP` 這幾個。8086 只有八個 16-bit 暫存器，而分派碼本身就吃掉兩個。
這一篇看的是：**哪幾個 p-machine 暫存器值得常駐在 8086 暫存器裡，其餘的放哪裡。**

> 延伸閱讀：[取指令與分派](dispatch-and-threading.md)｜[定址與活動記錄](addressing.md)｜
> [段的切換](segment-switching.md)

## 常駐暫存器

| 8086 | 內容 | 憑什麼這樣說 |
|---|---|---|
| `si` | **IPC**，指向下一個 opcode | 分派碼用 `lodsb`；每支會呼叫助手的常式都先 `mov ss:24h, si` 存起來 |
| `sp` | **SP**，求值堆疊頂 | `push`／`pop` 直接就是 p-code 的堆疊操作 |
| `bx` | **局部資料基底**，等於 `MP + 8` | 助手 `0x093e` 從 `bx − 8` 開始走靜態鏈；`RPU` 返回時寫 `word_26 = 新MP + 8` |
| `dx` | **全域資料基底**，等於 `Env_Data + 8` | `LAO` 直接 `add ax, dx`；`DVI`、`STP` 這些會弄髒 `dx` 的常式做完都補一句 `mov dx, ss:28h` |
| `ds` | 目前**程式碼段**的段基底 | `lodsb` 取的是 p-code；`CSP` 用完 `ds` 後從 `ss:2Ah` 還原 |
| `ss` | 直譯器自己的資料段 | 所有狀態變數都以 `ss:` 定址 |

`ax`、`cx`、`bp`、`di`、`es` 是工作用的。`di` 的出現次數（571）僅次於 `ax`，
因為分派碼每一輪都要用它算表位址。

**`dx` 那一句補救最能說明設計取捨。** 8086 的 `div` 與 `mul` 強制用掉 `dx`，
所以整數除法、packed 欄位寫入這些常式沒辦法保住全域基底。做法不是「不要放在 `dx`」，
而是「弄髒了就從記憶體補回來」——一個位元組的 `add ax, dx` 出現在每一個全域變數存取，
而 `mov dx, ss:28h` 只出現在少數幾支。

## 記憶體裡的狀態變數

以下偏移都是 `ss:` 相對的。「用到的常式」列的是實際觀察到的使用者，不是全部。

| 偏移 | 內容 | 用到的常式 |
|---|---|---|
| `0x24` | 存起來的 IPC（`si`） | 32 支，凡是要呼叫助手或切段的都存 |
| `0x26` | 局部資料基底 = `MP + 8`（`bx` 的記憶體副本） | `RPU` |
| `0x28` | 全域資料基底 = `Env_Data + 8`（`dx` 的副本） | `DVI`、`MPI`、`MODI`、`IXA`、`IXP`、`STP` |
| `0x2a` | 目前程式碼段的 8086 段值 | `CSP`、字串比較助手 |
| `0x2e` | **MP**，目前活動記錄 | `CPL`、`CPI`、`CXL`、`CXI`、`RPU`、`LSL` |
| `0x30` | **BASE**，`Env_Data` 原值 | `CPG` |
| `0x32` | 目前的 `MSPROC`（程序號） | `RPU` |
| `0x34` | 目前段的 SIB | 切段助手 |
| `0x36` | 程序字典基底（段內偏移 ×2） | 呼叫助手 `0x101b` |
| `0x3a` | **E_Vec**，以 segment number 索引的 E_Rec 指標陣列 | `LAE`、切段助手 |
| `0x3c` | 堆疊／堆積界線記錄 | 堆疊檢查助手 `0x02da` |
| `0x3e` | 目前的 **E_Rec** | `RPU`、切段助手 |
| `0x40` | 切段時暫存的「舊 E_Rec」 | `CPL`、`CPG`、`CPI`、`RPU` |
| `0x42` | **常數池基底**（段內位元組偏移） | `LCO`、`LDC`、`LDCRL`、`XJP` |
| `0x44` | **byte sex 旗標** | `LDC`、`MOV`、`XJP` |
| `0x46` | 堆疊檢查算出來的需求字數 | 堆疊檢查助手 |
| `0xce`、`0xd0`、`0xd2`、`0xd4`–`0xda` | 各類暫存 | `LDC`、`SRS`、集合運算、呼叫序列 |
| `0x110` | 單調遞增的計數器，寫進 SIB 的 `Activity` | 切段助手 `0x10f5` |

`0x2270`–`0x227c` 那七個 word 只有 `ADR`、`SBR`、`MPR`、`DVR` 用，
是浮點常式的暫存器保存區——那四支會把 `si`、`ax`、`bx`、`di` 整批 `xchg` 出去再換回來。

## byte sex 不是猜的

`0x44` 這一格能直接對上手冊。IV.0 的 `MOV`（197）定義寫著：
「UB 為 2 且本段 byte sex 與主機相反時，搬運時逐 word 交換位元組」。8086 版的 `MOV`：

```
0a13: 0bed        or   bp, bp            ; UB
0a15: 7421        jz   一般搬運
0a17: 83fd02      cmp  bp, 2
0a1a: 7524        jnz  一般搬運
0a1c: 36833e440001 cmp word ptr ss:44h, 1
0a22: 741c        jz   一般搬運
0a24: ad          lodsw                  ; 逐 word 搬並交換位元組
0a25: 86c4        xchg al, ah
0a27: ab          stosw
0a28: e2fa        loop
```

`LDC`（131，運算元是 `UB_1, B, UB_2`）與 `XJP`（214）用同一組判斷。
**`ss:44h` 為 1 表示段的 byte sex 與主機相同。** 這個值在切段時從程式碼段的
表頭第 `0x0c` 個位元組讀出來（見[段的切換](segment-switching.md)）。

## 錯誤怎麼發

所有執行期錯誤走同一條路：把錯誤碼放進 `bp`，跳 `0x020f`。

```
025a: bd0b00  mov bp, 11   ; 未實作的指令，44 格指向這裡
0269: bd0e00  mov bp, 14   ; 只有 0xff
026e: bd1000  mov bp, 16   ; BPT
```

`0x40`–`0x5f`、`0xaa`、`0xaf`、`0xf5`–`0xfe` 這 44 格全部指向 `0x025a`。
IV.0 手冊把 `0xfa`–`0xff` 標成 `RESERVE1`–`RESERVE6`，
但這份直譯器把最後一格 `0xff` 拿去指向錯誤 14——**同一版、同一張表，最後一格的分配
與 68000 版不同**。

## 邊界

- 「用到的常式」是從 169 支 dispatch 目標與 25 支助手的反組譯裡數出來的，
  沒有涵蓋反組譯截斷之後的部分。
- `0x3c` 指向的記錄只用了 `+4` 那一格，整個記錄的版面沒有解。
- `0xce` 之後那幾格的用途是從個別常式推的，沒有一致的命名。
