# アドレッシング：p-code のワード世界から 8086 のバイト世界へ

[English](addressing.en.md) ｜ **日本語** ｜ [繁體中文](addressing.md)

p-code のアドレス単位はワードで、変数番号は 1 から始まる。8086 のアドレス単位はバイトだ。
この稿では両者のあいだにある換算層と、活動記録の実際の版面を見る。

> 関連：[インタプリタの状態](machine-state.ja.md)｜
> [セグメント切り替え](segment-switching.ja.md)

## 可変長オペランド：同じコードが 7 回書き写されている

マニュアル p.16 の big operand 規則はこうだ——**先頭バイトの最上位ビットが 0 なら
その値そのもの（0–127）、1 なら下位 7 ビットを上位バイトとし、もう 1 バイト読んで
下位バイトとする（0–32767）。** 8086 版は毎回その場に展開する：

```
ac        lodsb
98        cbw
84c0      test al, al
7905      jns  +5              ; 最上位ビットが 0 → そのまま使う
247f      and  al, 7Fh
86e0      xchg ah, al          ; 下位 7 ビットが上位バイトになる
ac        lodsb                ; もう 1 バイト読んで下位バイトに
d1e0      shl  ax, 1           ; ← ワード・オフセット ×2 = バイト・オフセット
```

この 9 バイト列（`84 c0 79 05 24 7f 86 e0 ac`）はファイル中に **19 回**、
一字一句同じ形で現れる。`LCO`、`LDC`、`LAO`、`XJP`、`RPU`、`MOV` と 2 本の
アドレッシング・ヘルパがその使用者だ。サブルーチンにしなかった理由はコード自身が
語っている。全体で 15 バイト、`call` と `retn` に置き換えれば 4 バイトと制御転送 2 回——
**いちばん熱い経路では、呼び出しのほうが重複バイトより高くつく。**

末尾の `shl ax, 1` は、このインタプリタ全体で 160 回現れる動作である。p-code が
「5 番目のワード」と言うとき、8086 が欲しいのは「10 番目のバイト」だからだ。

## 活動記録：なぜどの基底にも 8 を足すのか

`MOV`／`LOD`／`STR` の族が局所変数に触るとき、アドレスは `bx + 8 + 2×番号`。
大域なら `dx + 2×番号` で、`dx` はセグメント切り替え時に `Env_Data + 8` に設定される。
どちらも 8 を足している——足しているのは Mark Stack Control Word の長さだ。

マニュアル Figure 5 が示す MSCW のフィールド順は `MSSTAT`、`MSDYN`、`MSIPC`、`MSENV`、
`MSPROC` の 5 ワード。`RPU` はそれをまとめて pop するので、順序は一目でわかる：

```
1140: a12e00    mov ax, word_2E      ; MP
1143: 48 48     dec ax; dec ax       ; sp ← MP−2
1145: 8be0      mov sp, ax
1147: 5f        pop di               ; [MP−2]
1148: 5b        pop bx               ; [MP+0]  MSSTAT
1149: 5b        pop bx               ; [MP+2]  MSDYN  → 新しい MP
114a: 891e2e00  mov word_2E, bx
114e: 83c308    add bx, 8            ; 新しい局所データ基底
1151: 891e2600  mov word_26, bx
1155: 5e        pop si               ; [MP+4]  MSIPC
1156: 58        pop ax               ; [MP+6]  MSENV
1157: 5d        pop bp               ; [MP+8]  MSPROC
1158: 0326d400  add sp, word_D4      ; 引数を削る
115c: 892e3200  mov word_32, bp
1160: 85ed      test bp, bp
1162: 7811      js  ...              ; 手続き番号が負 → EXITIC へ
```

つまり基底に 8 を足したあと、**番号 1 の変数は `MP+10`、ちょうど MSCW の直後の
最初のワードに落ちる**。p-code の変数番号が 1 から始まるのは慣習の問題ではなく、
版面から出てくる帰結である。

`test bp, bp; js` の 2 行は、マニュアルの `RPU` の記述と一致する——「MSCW 内の
手続き番号が < 0 なら、MSCW の IPC ではなくその手続きの EXITIC へ復帰する」。

## 中間レベルの変数：静的チェーンを辿る

`LOD`／`STR`／`LDA` の第 1 オペランドはレベル差 `DB`。ヘルパ `0x093a`：

```
093a: 32e4      xor  ah, ah
093c: ac        lodsb                ; DB
093d: 91        xchg ax, cx
093e: 8beb      mov  bp, bx          ; ← SLOD1 / SLOD2 はここから入る
0940: 83ed08    sub  bp, 8           ; MP に戻す
0943: e305      jcxz +5
0945: 8b6e00    mov  bp, [bp+0]      ; MSSTAT：一段外へ
0948: e2fb      loop
094a: <big operand デコード>
0955: d1e0      shl  ax, 1
0957: 03e8      add  bp, ax
0959: 83c508    add  bp, 8
095c: c3        retn
```

`bx` は 8 を足した基底なので、チェーンを辿るにはまず引き戻し、辿り終えてから足し直す。
`SLOD1`、`SLOD2` は「レベル差が 1 または 2 に固定」の短縮形で、自分で `cx` を設定し、
**`0x093e` から入って `DB` を取る 3 バイトを飛ばす**——一つのコードに二つの入口。

セグメントをまたぐ大域（`LAE`／`LDE`／`STE`）は別の道を通る：

```
15d2: 32e4      xor ah, ah
15d4: ac        lodsb                ; セグメント番号
15d5: 95        xchg ax, bp
15d6: d1e5      shl bp, 1
15d8: 368b3e3a00 mov di, ss:3Ah      ; E_Vec
15dd: 8b2b      mov bp, [bp+di]      ; E_Vec[seg] → E_Rec
15df: 8b6e00    mov bp, [bp+0]       ; E_Rec.Env_Data
15e2: <big operand デコード>
15ef: 050800    add ax, 8
15f2: 03e8      add bp, ax
```

同じ「8 を足す」。違いは基底が常駐の `dx` ではなく `E_Vec` から引かれる点だけだ。

## 復帰：道は一本ではなく三本

`RPU`（@0x1102）が活動記録を解体したあと、**どこへ跳ぶかは 2 つの値の形で決まる**：

```
1155: pop si            ; MSIPC
1156: pop ax            ; MSENV、捨てる
1157: pop bp            ; MSPROC
1158: add sp, word_D4   ; 引数を削る
115c: mov word_32, bp
1160: test bp, bp
1162: js  1175          ; MSPROC が負 → EXITIC へ
1164: test si, si
1166: jz  11A5          ; MSIPC が 0  → ネイティブ・コードへ復帰
1168: 通常経路：MSIPC から続行
```

**MSPROC が負なのは、その枠が `EXIT` によって解体されつつあることを意味する。**
Pascal の `EXIT(proc)` は一度に何段も抜けられる。仕組みは途中の各枠の `MSPROC` を
負にすることで、復帰時に負号を見たら `MSIPC` へ戻らず、その手続き自身の**退場コード**
（`EXITIC`）へ跳ぶ：

```
1175: neg word_32       ; 負号を外す
1179: shl bp            ; bp はまだ負 → 次行が「辞書基底 − 2×手続き番号」になる
117b: add bp, word_36
117f: mov bp, es:[bp]   ; 辞書項目、指しているのは DATASIZE
1183: dec bp            ; 1 ワード戻す ＝ EXITIC
1184: shl bp
1186: mov ax, es:[bp]
118a: test si, si
118c: jz  11A1
118e: cmp si, ax
1190: jae 1194          ; 復帰点が既に退場コードより後ろ → そのまま使う
1192: mov si, ax
```

最後の比較が肝である。**2 つのアドレスのうち後ろのほうを取る。** 退場コードを既に
通り過ぎているなら戻ってはいけない。さもないと `finally` にあたる部分が 2 回走る。

**MSIPC が 0 なのは、この枠を呼んだのがネイティブ・コードだという意味**（@0x11A5 は
`lret`）。p-code 側に跳ぶ先が無いので、制御を機械語の世界へ返すしかない。

三つの道の違いは 2 ワードの符号とゼロだけ。間違えてもその場ではエラーにならず、
ただ別の場所を実行するだけである。

## packed フィールド：表引きは計算より安い

マニュアル p.47 は packed フィールドのアドレスをスタック上の 3 ワードと定義する——
アドレス、ビット数、いちばん右のビット番号。8086 版の `LDP`：

```
0a77: 59        pop cx               ; いちばん右のビット番号
0a78: 58        pop ax               ; ビット数
0a79: 5d        pop bp               ; ワード・アドレス
0a7a: 8b6e00    mov bp, [bp+0]
0a7d: d3ed      shr bp, cl           ; フィールドを最下位へ寄せる
0a7f: 95        xchg ax, bp
0a80: d1e5      shl bp, 1            ; ビット数 ×2 を添字に
0a82: 2e2386b61f and ax, cs:[bp+1FB6h]
```

`0x1fb6` からは出来合いのマスク表が置かれている：

```
0000 0001 0003 0007 000f 001f 003f 007f
00ff 01ff 03ff 07ff 0fff 1fff 3fff 7fff ffff
```

第 n 項は `(1 << n) − 1`。`STP` も同じ表からマスクを取り、`ror`／`rol` でフィールドを
所定の位置に回す：

```
0a91: 5f        pop di               ; 格納するデータ
0a92: 59        pop cx               ; いちばん右のビット番号
0a93: 5d        pop bp               ; ビット数
0a94: d1e5      shl bp, 1
0a96: 2e8b86b61f mov ax, cs:[bp+1FB6h]
0a9b: 23f8      and di, ax           ; データをフィールド幅に切る
0a9d: f7d0      not ax               ; 反転マスク
0a9f: 5d        pop bp               ; ワード・アドレス
0aa0: 8b5600    mov dx, [bp+0]
0aa3: d3ca      ror dx, cl           ; フィールドを最下位へ回す
0aa5: 23d0      and dx, ax           ; フィールドを消す
0aa7: 0bd7      or  dx, di           ; 新しい値を入れる
0aa9: d3c2      rol dx, cl           ; 回して戻す
0aab: 895600    mov [bp+0], dx
0aae: 368b162800 mov dx, ss:28h      ; 大域基底を戻す
```

`ror`／`rol` の対は「左シフトしてから右シフト」よりシフトが 1 回少ない。代償は
反転マスクが要ることだが、それは `not` 一命令で済む。

同バージョンの 68000 インタプリタにこの表は無く、「左シフトしてから右シフト、
シフタをマスク生成器として使う」方式をとる。どちらも「実行時にマスクを計算する」
ことを避けている——フィールド幅が実行時の値だからだ。手段は命令セットが決める。

`IXP` は「基底＋添字」をあの 3 つ組に変える。両 CPU とも 1 回の除算で商と剰余を
同時に得る：

```
0a50: 32e4 ac   xor ah,ah; lodsb     ; UB_1：1 ワードあたりの要素数
0a53: 95        xchg ax, bp
0a54: 32e4 ac   xor ah,ah; lodsb     ; UB_2：フィールドのビット幅
0a57: 91        xchg ax, cx
0a58: 58        pop ax               ; 添字
0a59: 5f        pop di               ; 基底
0a5a: 33d2      xor dx, dx
0a5c: f7f5      div bp               ; ax = 何番目のワード、dx = 何番目の枠
0a5e: d1e0      shl ax, 1
0a60: 03f8      add di, ax
0a62: 57        push di              ; 3 つ組：アドレス
0a63: 51        push cx              ;         ビット数
```

## 境界

- 「19 回」はファイル全体でバイト列を数えた結果なので逆アセンブルの打ち切りの影響を
  受けない。ただし列の照合は完全一致だけを拾うので、変形したデコードは数に入らない。
- `LDP`／`STP` のスタック順序はマニュアルの `Pack-ptr` の定義と項目ごとに一致する。
  これは両 CPU 版で検証済み。
- `IXP` が除算で「何番目のワード」を求める以上、フィールドはワード境界をまたがない
  ことが前提になる。コンパイラがどう保証しているかは本稿では追っていない。
