# 多工與換 task：三條串列與一招

[English](tasking.en.md) ｜ [日本語](tasking.ja.md) ｜ **繁體中文**

UCSD Pascal 有 `PROCESS`、`START`、`SEMAPHORE`——一台 1978 年的機器上就有
真正的並行。這一篇看的是 8086 版怎麼做到的。

結論先講：**它只碰資料段裡的三條串列**，而換 task 那一刻用了一招
看起來很粗暴、但省下整個判斷的做法：**把整張 dispatch 表填成同一個位址**。

> 延伸閱讀：[直譯器的狀態](machine-state.md)｜[取指令與分派](dispatch-and-threading.md)

## 三條串列

| 位置 | 是什麼 |
|---|---|
| `ss:38h` | ready queue 的頭。**跑著的那個 task 一直在裡面，而且在最前面** |
| `ss:3Ch` | 目前是哪個 task（指向它的 TIB）|
| 號誌 `+2` | 在等這個號誌的 TIB 串列 |

串列的「下一個」放在 TIB 的 `+0`，優先權放在 `+2` 的**低位元組**
（高位元組是旗標，@0x17C4 的 `mov al,[bx+2]` 只取一個位元組）。

TIB 其餘用得到的欄位：

| 偏移 | 是什麼 |
|---|---|
| `+08` | SP |
| `+0A` | MP |
| `+0E` | IPC |
| `+10` | E_Rec |
| `+12` | MSPROC ＋ `ss:0E6h`（高位元組）|
| `+14` | 在等哪個號誌；不在等就是 0 |

## 號誌

號誌是兩個 word：計數與等待佇列的頭。

**`WAIT`（@0x1755）**：計數不是 0 就減一，走人。是 0 就
把自己從 ready queue 拿掉（@0x1722）、依優先權排進號誌的等待佇列（@0x16E9）、
在 `TIB+14h` 記下在等哪個號誌，然後換人。

**`SIGNAL`（@0x17D5 → 助手 @0x1791）**：計數為負或沒有人在等就加一，走人。
有人在等就把佇列頭那個叫起來、清它的 `+14h`、依優先權放進 ready queue，
**叫起來的那個優先權不低於自己才換人**（@0x17C7 的 `jb`）。

排隊那一支（@0x16E9）走到第一個優先權**比它低**的前面停下來——
同優先權排在後面，所以先等的先被叫到。

## 換人那一招

換 task 不能在指令中間發生。原版的做法不是去判斷「現在能不能換」，
而是**把整張 dispatch 表的 256 格全部填成同一個位址**：

```
18a6: push es; push di; push cx
18a9: xor di,di
18ac: push cs; pop es
18ae: mov cx, 0x100
18b1: rep stosw          ; 256 個 word 全部填成 ax
```

於是**下一條指令無論是什麼，都會落到那個位址**。
換完之後再把表抄回來（@0x1892，從 `0x1D56` 搬 512 個位元組回偏移 0）。

落點是 @0x17E8：

```
17e8: dec si             ; 把已經被 lodsb 取走的那個位元組還回去
17e9: call 0x15F5        ; 整份狀態存進目前的 TIB
17ec: call 0x1892        ; 把 dispatch 表抄回來
17ef: bp = ss:34h; call 0x10F5   ; 目前這一段記一次 activity
17f7: call 0x1837        ; 關中斷
17fa: bp = ss:38h        ; ready queue 的頭
17ff: ss:3Ch = bp        ;   成為目前的 task
1804: call 0x1623        ; 整份狀態從新的 TIB 讀回來
1807: call 0x183c        ; 開中斷
180a: 新段在記憶體嗎？不在就發 segment fault
```

那個 `dec si` 就是這一招的代價：陷阱是在 `lodsb` **之後**才生效的，
所以要把那個位元組吐回去。

**這一招值得記的地方在於它避開了什麼。** 「現在能不能換」是一個要在
每條指令都問一次的問題；把它變成「讓下一次取指令自己掉進來」，
就一次都不用問。代價是換人那一刻要多搬兩次 512 個位元組——
換 task 本來就不常發生，這個交換划算。

一台一條一條走的重製機器不需要這一招：在指令的結尾換就是同一件事。
但**不知道這一招的話，`dec si` 會看起來像個 bug**。

## 存與還原

`@0x15F5` 存：`[TIB+8]=SP`、`+0A=MP`、`+0E=IPC`、`+10=E_Rec`、
`+12=MSPROC|ss:0E6h<<8`。

`@0x1623` 還原：先 `MSPROC`，再 `E_Rec`（連帶把 `Env_Data`、`E_Vec`、`SIB`、
程式碼段值、程序字典、byte sex、常數池整組換掉），最後 `IPC`、`MP`、`SP`。
**它不檢查段在不在記憶體**——那是呼叫端的事（@0x180A）。

`SPR`（寫處理器暫存器）也走這條：存進 TIB、寫那一格、再整份讀回來。
寫的若是暫存器 −1（`ss:3Ch`），那一步就是換 task。

## 邊界

- ready queue 的插入與移除、號誌的兩條路、換人那一段都逐條讀過碼，
  並且在[自舉](../30-remake/specs/03-boot.md)裡實際跑過。
- 中斷那一側只讀到 `ATTACH`（把號誌掛到 `ss:4Eh` 的向量表）與
  @0x1878 的分派；真正的中斷來源沒有追。
- `TIB+04`／`+06`（堆疊上下界）由 bootstrap 填，怎麼算的還沒解。
