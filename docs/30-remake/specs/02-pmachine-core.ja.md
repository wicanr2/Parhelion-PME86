そのままバイトに戻って照合できる。

## 1. 実行状態

1.1 セグメントは 2 つで足りる。コードが 1 つ（`ds`、`lodsb` がフェッチする場所）、
評価スタック・局所変数・大域変数がもう 1 つ（`ss`）。

1.2 常駐する基底（`docs/10-interpreter/machine-state.ja.md`）：

| 欄 | 何か | オリジナルの置き場所 |
|---|---|---|
| `IPC` | 次の opcode のセグメント内バイト・オフセット | `si` |
| `SP` | 評価スタックの頂点。低位へ伸びる | `sp` |
| `Local` | 局所データ基底 ＝ `MP + 8`。変数 n は `Local + 2n` | `bx`（複製は `ss:26h`） |
| `Global` | 大域データ基底 ＝ `Env_Data + 8` | `dx`（複製は `ss:28h`） |
| `ConstPool` | コード・セグメント内の定数プールのバイト・オフセット | `ss:42h` |
| `ProcDict` | コード・セグメント内の手続き辞書のバイト・オフセット | `ss:36h` |
| `Proc`／`Env` | 現在の `MSPROC` と `E_Rec` | `ss:32h`／`ss:3Eh` |

1.3 `Proc` と `Env` をモデル化しないわけにはいかない。計算には関与しないが、
**呼び出し時に MSCW へ保存する必要がある**——1 つ落とせばスタックの内容がオリジナルと
1 ワードずれ、以後すべての `SP` が狂う。

## 2. 命令フェッチ

2.1 opcode は 1 バイト。可変長オペランド（`big`）は最上位ビットが 0 ならその値そのもの
（0–127）、1 なら下位 7 ビットを上位バイトとし、さらに 1 バイト読んで下位バイトとする
（0–32767）。このコードはインタプリタ内で 19 回その場に展開されている。

2.2 **`big` はほぼ必ず 2 倍する**。p-code はワードで語り、メモリはバイトで番地付けされる。
唯一の例外は `NAT-INFO`（`0xa9` @0x075f）で、`shl` の無い `add si, ax` を行う——
これは読み飛ばすネイティブ・コードのバイト数だからだ。

## 3. 短縮形

| opcode | 意味 | 出典 |
|---|---|---|
| `0x00`–`0x1f` `SLDC` | opcode 自身を積む | @0x0319、@0x0322（`shr di,1; push di`） |
| `0x20`–`0x2f` `SLDL` | `[Local + 2n]` を積む | @0x032d（`mov bp,bx`） |
| `0x30`–`0x3f` `SLDO` | `[Global + 2n]` を積む | @0x03fd（`mov bp,dx`） |
| `0x60`–`0x67` `SLLA` | `Local + 2n`（アドレス）を積む | @0x04cd（`sub di,0BEh; add di,bx`） |
| `0x68`–`0x6f` `SSTL` | `[Local + 2n]` へ格納 | @0x04dd |
| `0x78`–`0x7f` `SIND` | TOS をアドレスとみなし `[TOS + 2n]` を積む | @0x0554 |

## 4. アドレッシングとデータ転送

`LDCB`(@0x05b4)、`LDCI`(@0x05bf)、`LCO`(@0x05ca)、`LLA`(@0x05e6)、`LDO`(@0x05ff)、
`LAO`(@0x061b)、`LDL`(@0x0634)、`STL`(@0x070a)、`SRO`(@0x0726)、`LDB`(@0x0751)、
`STB`(@0x0822)、`STO`(@0x0814)、`IND`(@0x08d7)、`LDM`(@0x09b8)、`DUP1`(@0x08bc)、
`LDCN`(@0x0693)、`NOP`(@0x06b9)、`NAT-INFO`(@0x075f)。

中間レベル（`LDA` @0x0650、`LOD` @0x065d、`STR` @0x0742、`SLOD1/2` @0x0775/@0x0787）は
ヘルパ @0x093a を共有する——`bp = bx − 8` で MP に戻り、DB 回だけ `bp = [bp]`
（`MSSTAT` は MP+0）、最後に `bp += 2n + 8`。`LSL`（@0x14ee）は同じ辿り方だが、
積むのはそのレベルの MP である。

## 5. 算術と比較

5.1 2 項命令は一律 `pop ax; pop bp; op bp, ax`——**TOS が右オペランド**である。
逆にすると `EQUI` では差が出ず、`LEQI` は完全に反転する。

`LOR`(@0x06d2)、`LAND`(@0x06e0)、`ADI`(@0x06ee)、`SBI`(@0x06fc)、
`MPI`(@0x066c、`imul` の下位 16 ビット)、`DVI`(@0x067f)、`MODI`(@0x0bbc)、
`NGI`(@0x08af)、`ABI`(@0x089a)、`LNOT`(@0x08ca、ワード全体を反転)、
`BNOT`(@0x06c2、反転して最下位ビットだけ残す)、`INC`(@0x08f2)、`DECI`(@0x0918)、
`IXA`(@0x0864)。

5.2 `MODI` の剰余が負のときは除数の絶対値を加える（@0x0bbc の `test dx,dx; jns` の部分）。
Pascal の `MOD` は C の `%` ではない。

5.3 比較はすべて同じ形をとる。`cmp bp,ax` のあと、条件が成り立てば 1、さもなくば 0 を積む。
`EQUI`(@0x0799)、`NEQI`(@0x07ab)、`LEQI`(@0x07be)、`GEQI`(@0x07d0) は符号付き。
`LEUSW`(@0x07e2)、`GEUSW`(@0x07f4) は符号無し。

## 6. 分岐

6.1 変位は**オペランドの後ろから**数える。オリジナルが先に `lodsb`／`lodsw` を行い、
そのあと `add si, ax` するからだ。

6.2 条件分岐が見るのは **TOS の最下位ビット**（`shr ax,1` でキャリーに取る）であって、
ワード全体がゼロかどうかではない。値が 2 のとき、2 通りの読み方は逆の答えを出す。

`UJP`(@0x0c47 バイト)、`JPL`(@0x0c84 ワード)、`FJP`(@0x0848)、`FJPL`(@0x0c74)、
`TJP`(@0x0c38)、`EFJ`(@0x0c54 等しくなければ跳ぶ)、`NFJ`(@0x0c64 等しければ跳ぶ)。

> **ここで踏んだ落とし穴は規則として書く価値がある。** Go は `a + b` の 2 つの
> オペランドの評価順を規定しないので、
> `s.IPC = uint16(int16(s.IPC+1) + int16(int8(s.fetch())))` は当たったり外れたりする——
> `s.IPC+1` が、`fetch()` が既に IPC を進めた**あと**に読まれうるからだ。
> **相対アドレスは必ずオペランドを先に変数へ取り出してから計算する。**
> このバグは突き合わせが 101 条目で捕まえた。コードを静的に眺めても見えない。

## 7. packed フィールド

`LDP`(@0x0a77)、`STP`(@0x0a91)、`IXP`(@0x0a50)。3 つ組の順序はアドレス、ビット数、
いちばん右のビット番号（`docs/10-interpreter/addressing.ja.md`）。

オリジナルは `cs:1FB6h` の出来合いのマスク表（第 n 項 ＝ `(1<<n)−1`）を使う。
ここでは直接計算しており、結果は同じ。**これは再実装独自の実装手法であって挙動の差ではない**——
あの表が存在する理由は 8086 でマスクを計算するのが表引きより高くつくからで、
Go にその問題は無い。

`IXP` は 1 回の除算で「何番目のワード」と「ワード内の何番目の枠」を同時に得る
（@0x0a50 の `div bp`）。

## 8. 同一セグメントの呼び出しと復帰

8.1 `CPL`(@0x1310)、`CPG`(@0x1337)、`CPI`(@0x1368)、`SCPI1`／`SCPI2` は
@0x101b → @0x103a → @0x1057 を共有する。違いは静的リンクの出所だけ：

| 命令 | 静的リンク |
|---|---|
| `CPL` | 呼び出し側自身の MP |
| `CPG` | `BASE`（＝ `Global − 8`） |
| `CPI`／`SCPIn` | DB 段だけ外へ辿ったそのレベルの MP |

8.2 辞書項目が指すのは `DATASIZE` で、最初の命令はその 1 ワード後ろ（spec 01 §5.4）。
`DATASIZE` が負ならネイティブ・コードであり、ここではエラーを返す。

8.3 局所データの確保は `SP −= 2 × DATASIZE`（@0x02da が算出する値から、
呼び出し時にスタックへ積まれたものを差し引くとこれになる）。

8.4 MSCW の積む順序（@0x1057）は `MSPROC`、`MSENV`、`MSIPC`、`MSDYN`、`MSSTAT`。
スタックは下へ伸びるので、MP から上へ読むと Figure 5 の欄順になり、
局所変数は `MP+10` から始まる。**順序を誤ると、呼ばれた側の局所変数が制御欄を潰す。**

8.5 `RPU`(@0x1102) がそれを解体する。`SP = MP − 2` として順に `[MP−2]`、`MSSTAT`、
`MSDYN`（これが新しい MP になる）、`MSIPC`、`MSENV`、`MSPROC` を取り、
最後に `SP += 引数のバイト数`。MSCW の `E_Rec` が現在のものと異なればセグメント間復帰で、
8.11 を見よ。

## 8bis. セグメント間呼び出し

8.6 `SCXG`(@0x0545)、`CXL`(@0x13b8)、`CXG`(@0x13eb／@0x1413)、`CXI`(@0x1457／@0x1475) は
同じ道を共有する——**まずセグメントを切り替え、そのあと同一セグメントと同じ方法で枠を作る。**
`SCXG n` は `CXG` であり、セグメント番号は opcode に埋め込まれている
（`shr di,1; sub di,6Fh`）。

静的リンクの出所は、`CXL` が呼び出し側の MP、`CXG`／`SCXG` が**目標セグメント**の `BASE`
（@0x1420 の `push word_30`。`word_30` は切り替えで既に新しくなっている）、
`CXI` は DB 段だけ外へ辿る。**切り替えより前に計算する必要がある**——
チェーンを辿るのは呼び出し側の仕事だからだ。

8.7 セグメント切り替えは**一式まとめて**である。コード、`Env_Data`、手続き辞書、
定数プール、`E_Rec` が同時に入れ替わる。1 つ漏らしてもエラーにはならない——
定数プールを替えなければ別セグメントの定数を読み、辞書を替えなければ別セグメントの
手続きを呼ぶ。どちらも静かにデータらしきものを読むだけだ。

8.8 MSCW の `MSENV` には**呼び出し側**の `E_Rec` を記録する。オリジナルは @0x1057 で
新しい方を積み、@0x10db で旧い方に書き戻す。最初から旧い方を積んでも効果は同じ。
誤って記録すると、復帰時に戻せなくなる。

8.9 セグメントが常駐していないとき、オリジナルは命令の先頭まで戻って segment fault を
発生させ、OS がロードしたあとで**同じ命令をやり直す**（@0x143d の `si = ss:24h; dec si`）。
ここでは `ErrNotResident` を返す——ロードはホストの仕事だからだ。

8.10 **セグメント 1 の手続きはホストに埋め込まれたネイティブ・コードでありうる**
（マニュアル p.66）。オリジナルの `CXG` は**切り替える前に**その表を引き（@0x13f4）、
当たればセグメントを一切切り替えずに機械語へ直接跳ぶ。先に切り替えてから気づくと
半分だけ切り替わった状態が残り、しかもそれはエラーにならない。

8.11 `RPU` において MSCW の `E_Rec` が現在のものと異なればセグメント間復帰であり、
先にセグメントを戻す必要がある（@0x1102 の `bp = [MP+6]; cmp bp, word_3E`）。

8.12 **`Environment` 層は意図的に p-machine の外に置いている。** セグメント番号が
メモリ上のどこに対応するかは `E_Vec`、`SIB`、Codepool に関わる——それは OS のデータ構造で、
ホストが変われば全く別物になる。p-machine は「そのセグメントの姿をくれ」としか問わない。

実装側（`oracle/parity.go` の `liveEnv`）は @0x0fba の方法で計算する：

```
セグメント値 ＝ paragraph(Codepool 基底) ＋ (プール内オフセット ÷ 16)
```

`Seg_Base` は `SIB` 先頭の 2 ワード——Codepool 基底へのポインタ（`ss` 相対）と
プール内バイト・オフセット。詳細と実測値は
`docs/10-interpreter/segment-switching.ja.md` を参照。

## 9. 検証

`oracle/conform_test.go` の `TestParityAgainstTheOriginal`——オリジナルのその時点の状態から
展開し、両者を一条ずつ walk して、各条のあとに `IPC`、`SP`、`TOS` を比較する。
3 項目のいずれか 1 つでも合わなければ止まる——続けてもエラーが積み重なって
読めない雑音になるだけだ。

**止まり方 3 種は区別できる**——walk し終わった、未実装の命令に当たった、本当に食い違った。
失敗なのは 3 番目だけで、2 番目は進捗であり、次に手を付けるべき 1 本を正確に示す。

現在：**224,987 条が一条ずつ一致、使用 opcode 173 種、食い違い 0。**

比べるのは 4 項目——次の命令のアドレス、スタック頂点の位置と内容、現在の E_Rec。
さらに **p-code 1 条につきオリジナル側に 8086 命令 40 万条の予算**を与えている。
起動後の段階では 2 条のあいだでディスクを待ち、キーボードをポーリングするので、
予算が足りないと「オリジナルにもうやることが無い」と誤判定して早々に切り上げてしまう。
止まる理由は**オリジナルにやることが無くなったから**——起動が走り終わり、
システムはキーボード待ちのループに座っている。そこまで行けたということは、
その区間すべてを突き合わせたということであり、それは終了であって失敗ではない。

別に **147 条はオリジナル自身に walk させている**——すべてセグメント 1 の埋め込み
ネイティブ手続きだ。あれはインタプリタ自身の機械語であって p-machine の意味論ではないので、
オリジナルが実行し終えたあと状態を写し取って続行する。**これらの条は検証されていない**。
分母は「一条ずつ一致」の数字を見ること。

通しているのは 4 種類だけで、いずれも p-machine が定義上手放すべきものである——
セグメント 1 の埋め込みネイティブ手続き、`NAT`（8086 の機械語へ跳ぶ。実行には本物の
8086 が要る）、セグメントが未ロード（OS がディスクから読みに行く）、
タスク切り替え（スケジューラが状態一式を別の TIB のものに入れ替える）。
**p-code 命令の未実装は含まない。** それも写し取ってしまえば「まだ作っていない」が
「作り終えた」に見え、突き合わせの意味が失われる。テストは、飛ばした opcode が
本当にセグメント間呼び出しの族だけであることを確認する。

セグメント間呼び出しにはさらに 2 つの検査がある：

- `TestSegmentResolutionMatchesTheOriginal`——こちらが算出したコード・セグメントの内容、
  大域基底、手続き辞書、定数プールが、オリジナルが切り替えたあとのものと**4 項目とも完全に一致**する。
  これが特に重要なのは、`Seg_Base` の換算法がマニュアルの記述ではなく実測だからだ。
  誤ったときの症状は「別セグメントの途中へ跳ぶ」であり、エラーにはならない。

  切り替えの捕捉は `dosgolem` の `WatchWord` でインタプリタの `E_Rec` を監視して行い、
  **ポーリングはしない**。2 条の p-code のあいだに切り替わって戻ることがあり、
  ポーリングでは取り逃がす——そして取り逃がしてもエラーにはならず、
  一部の切り替えが「起きなかったこと」に見えるだけだ。監視に変えたところ、
  1 本のトレース中の**45 回の切り替えをすべて受け取り、個別に検証**できた
  （ポーリングでは 3 回しか拾えていなかった）。
- `TestParityAcrossASegmentSwitch`——オリジナルを「次の 1 条がまさに切り替え」の地点まで
  進めてから展開し、**その切り替えを実際に一条ずつ walk する**（`E_Rec D7D2 → 0664`）。

テストは同時に下限（`parityFloor`）を釘付けにし、進捗が後退しないようにしている。

`internal/pmachine/` の下には、オリジナルの素材を必要としないテストがさらに 23 本ある。
手書きの p-code で、**突き合わせでは到達できない、あるいは到達しても見分けがつかない**
場合を釘付けにする：

| 何を釘付けにするか | なぜ突き合わせでは見えないか |
|---|---|
| 算術のオペランド順序 | 加算とビット演算は逆にしても結果が同じ |
| `MODI` の正負 4 通り | 被除数が正なら Pascal と C の `%` は一致する |
| 符号付きと符号無しの比較 | 小さな正数だけで試せばどちらも通る |
| `IXA` の添字 1 の近道 | 要素が 1 ワードなら両経路の結果が同じ |
| `LDM` の積む向き | 逆にしても各ワードは正当な値のまま |
| `LDB`／`STB` のバイト添字 | ワード添字として扱っても偶数位置は合ってしまう |
| 静的チェーンを辿る段数 | 段を誤っても読める値は正当なまま |
| ゼロ除算、`CHK` の範囲外、`ABI` の溢れ | 正常経路では到達しない |
| セグメント間呼び出しの埋め込み手続きは切り替え**前**に捕まえること | 先に切り替えると半分だけ切り替わった状態が残る |

各ケースの名前には `SYSTEM.PME.86` 内のファイル・オフセットが入っており、
合わないときはそのままバイトに戻って照合できる。

## 10. 集合の表現

スタック上の集合は **N ワードと、その頂点に N** という形で、ワード k は `sp + 2k` にある。
これは `INN`（@0x0dc6）の `sp += 2k; pop` から読み出したもので、推測ではない。

`SRS`（@0x0d4b）は部分範囲の集合を作り、境界は 0..4079 の中でなければならない。
`ADJ`（@0x0cac）は集合を固定 UB ワードに整え、**同時に長さを取り除く**——
以後その集合は固定長になり、長さを残すと以降すべての命令でスタックが 1 ワードずれる。

長さの規則は、和は長い方、積は短い方、差は左側を取る。比較のときは短い側をゼロ埋めとみなす。

`INN` はビットのマスクをマスク表の隣り合う 2 項の XOR で得る
（`cs:[1FB8h+2i] xor cs:[1FB6h+2i]` ＝ `1<<i`）——8086 ではシフトより安い。
ここでは直接計算しており、これは再実装独自の手法であって挙動の差ではない。

## 11. 浮動小数点

**8 バイトはそのまま IEEE 754 binary64、little-endian である。**
ヘルパ @0x22a8 から読み出した——`and ax,0Fh` が仮数の上位 4 ビット、
`and cx,7FF0h; shr 4` が 11 ビットの指数、`or al,10h` が隠れビットの復元。
符号は最上位バイトの bit 7（`ABR` @0x2a94 の `and byte [bp+7],7Fh`、
`NGR` @0x278c の `xor ... 80h`）。

> **マニュアル p.14 は実数を BCD 浮動小数点形式とするが、この版はそうではない。**
> 実装を正とする。1984 年には IEEE 754 が既に標準であり、変更は合理的だ。

`NGR` が符号を反転するのは 4 ワードが全部ゼロでないときだけ——そのまま符号反転すると
0 が −0.0 になり、ビット列が変わってしまう。
`LDCRL` のオペランドは定数プールの**ワード・オフセット**（`shl ax,1; add ax, ss:42h`）であって、
「何番目の実数定数」ではない。`STRL` のアドレスは実数の下に積まれている（`mov di,[si+8]`）。

## 12. マルチタスク

セマフォは 2 ワード——カウントと待ち行列の先頭（@0x1791 の `[di]`／`[di+2]`）。
**非ブロックの経路は加減算そのもの**である——`WAIT` は残高があれば 1 減らし、
`SIGNAL` はカウントが負か誰も待っていなければ 1 増やす。実際に並ぶか起こすときだけ
スケジューラへ入り、そのとき `TaskSwitch` を返す。

タスク切り替えは実行状態一式を別の TIB のものに入れ替える。それは OS のスケジューラであって、
1 命令の意味論ではない。`NAT` はもっと直接的だ——コード・セグメント内の 8086 機械語へ
`retf` で跳ぶ。これは**構造的に p-machine にできることではない**——
p-code をいくら書いても実行可能にはならない。この 2 つのエラー型は
「まだ作っていない」と区別できる。
