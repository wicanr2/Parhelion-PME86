# spec 02：p-machine 執行核心

| | |
|---|---|
| 狀態 | `CONFORMED`（涵蓋範圍內的 56 個 opcode）|
| 日期 | 2026-09-05 |
| 涵蓋 | 執行狀態、取指令、短形式、定址、算術、比較、跳躍、packed 欄位、同段與**跨段**呼叫與返回 |
| 不涵蓋 | 段 1 的內嵌原生程序、浮點、集合、字串、多工、CSP、多字搬移 |
| 驗證 | 逐條走 **306 條 p-code** 三項全同；段解析與原版**五項全同**；對拍實際走過一次真的換段 |

**每一條語意都是從 8086 版直譯器的碼讀出來的**，手冊只當交叉檢查。
下面標的位址都是 `SYSTEM.PME.86` 的檔案偏移，可以直接回去對碼。

## 1. 執行狀態

1.1 兩個段就夠：程式碼在一個段（`ds`，`lodsb` 取指令的地方），
求值堆疊、區域變數、全域變數全部在另一個段（`ss`）。

1.2 常駐的基底（`docs/10-interpreter/machine-state.md`）：

| 欄位 | 是什麼 | 原版放在 |
|---|---|---|
| `IPC` | 下一個 opcode 的段內位元組偏移 | `si` |
| `SP` | 求值堆疊頂，往低位址長 | `sp` |
| `Local` | 區域資料基底 ＝ `MP + 8`；變數 n 在 `Local + 2n` | `bx`（副本 `ss:26h`）|
| `Global` | 全域資料基底 ＝ `Env_Data + 8` | `dx`（副本 `ss:28h`）|
| `ConstPool` | 常數池在程式碼段裡的位元組偏移 | `ss:42h` |
| `ProcDict` | 程序字典在程式碼段裡的位元組偏移 | `ss:36h` |
| `Proc`／`Env` | 目前的 `MSPROC` 與 `E_Rec` | `ss:32h`／`ss:3Eh` |

1.3 `Proc` 與 `Env` 不模型化不行。它們不參與運算，但**呼叫時要存進 MSCW**——
少存一個，堆疊上的內容就與原版差一個 word，而後面每一條的 `SP` 都會跟著錯。

## 2. 取指令

2.1 opcode 一個位元組。變長運算元（`big`）最高位為 0 就是它本身（0–127），
為 1 則取低 7 位當高位元組、再讀一個位元組當低位元組（0–32767）。
這段碼在直譯器裡原地展開了 19 次。

2.2 **`big` 幾乎都要乘二**：p-code 說 word，記憶體按位元組定址。
唯一的例外是 `NAT-INFO`（`0xa9` @0x075f），它 `add si, ax` 沒有 `shl`——
那是要跳過的原生碼位元組數。

## 3. 短形式

| opcode | 語意 | 出處 |
|---|---|---|
| `0x00`–`0x1f` `SLDC` | 推 opcode 本身 | @0x0319、@0x0322（`shr di,1; push di`）|
| `0x20`–`0x2f` `SLDL` | 推 `[Local + 2n]` | @0x032d（`mov bp,bx`）|
| `0x30`–`0x3f` `SLDO` | 推 `[Global + 2n]` | @0x03fd（`mov bp,dx`）|
| `0x60`–`0x67` `SLLA` | 推 `Local + 2n`（位址） | @0x04cd（`sub di,0BEh; add di,bx`）|
| `0x68`–`0x6f` `SSTL` | 存進 `[Local + 2n]` | @0x04dd |
| `0x78`–`0x7f` `SIND` | 把 TOS 當位址，推 `[TOS + 2n]` | @0x0554 |

## 4. 定址與資料搬移

`LDCB`(@0x05b4)、`LDCI`(@0x05bf)、`LCO`(@0x05ca)、`LLA`(@0x05e6)、`LDO`(@0x05ff)、
`LAO`(@0x061b)、`LDL`(@0x0634)、`STL`(@0x070a)、`SRO`(@0x0726)、`LDB`(@0x0751)、
`STB`(@0x0822)、`STO`(@0x0814)、`IND`(@0x08d7)、`LDM`(@0x09b8)、`DUP1`(@0x08bc)、
`LDCN`(@0x0693)、`NOP`(@0x06b9)、`NAT-INFO`(@0x075f)。

中介層（`LDA` @0x0650、`LOD` @0x065d、`STR` @0x0742、`SLOD1/2` @0x0775/@0x0787）
共用助手 @0x093a：`bp = bx − 8` 回到 MP，走 DB 次 `bp = [bp]`（`MSSTAT` 在 MP+0），
最後 `bp += 2n + 8`。`LSL`（@0x14ee）是同一個走法，但推的是那一層的 MP。

## 5. 算術與比較

5.1 兩個運算元的指令一律 `pop ax; pop bp; op bp, ax`——**TOS 是右運算元**。
顛倒過來 `EQUI` 看不出差別，`LEQI` 會整個反過來。

`LOR`(@0x06d2)、`LAND`(@0x06e0)、`ADI`(@0x06ee)、`SBI`(@0x06fc)、
`MPI`(@0x066c，`imul` 取低 16 位)、`DVI`(@0x067f)、`MODI`(@0x0bbc)、
`NGI`(@0x08af)、`ABI`(@0x089a)、`LNOT`(@0x08ca，整個 word 取反)、
`BNOT`(@0x06c2，取反後只留最低位)、`INC`(@0x08f2)、`DECI`(@0x0918)、`IXA`(@0x0864)。

5.2 `MODI` 的餘數為負時要加上除數的絕對值（@0x0bbc 的 `test dx,dx; jns` 那一段）。
Pascal 的 `MOD` 不是 C 的 `%`。

5.3 比較全部走同一個形狀：`cmp bp,ax` 之後條件成立推 1、否則推 0。
`EQUI`(@0x0799)、`NEQI`(@0x07ab)、`LEQI`(@0x07be)、`GEQI`(@0x07d0) 帶號；
`LEUSW`(@0x07e2)、`GEUSW`(@0x07f4) 無號。

## 6. 跳躍

6.1 位移**從運算元之後算起**，因為原版是先 `lodsb`／`lodsw` 再 `add si, ax`。

6.2 條件跳躍看的是 **TOS 的最低位**（`shr ax,1` 取進位），不是整個 word 是否為零。
值是 2 的時候兩種讀法會得到相反的結果。

`UJP`(@0x0c47 位元組)、`JPL`(@0x0c84 word)、`FJP`(@0x0848)、`FJPL`(@0x0c74)、
`TJP`(@0x0c38)、`EFJ`(@0x0c54 不相等才跳)、`NFJ`(@0x0c64 相等才跳)。

> **這裡踩過一個坑，值得寫成規則。** Go 沒有規定 `a + b` 兩個運算元的求值順序，
> 所以 `s.IPC = uint16(int16(s.IPC+1) + int16(int8(s.fetch())))` 會時對時錯——
> `s.IPC+1` 可能在 `fetch()` 已經推進 IPC **之後**才被讀到。
> **相對位址一律先把運算元取出來放進變數再算。**
> 這個 bug 是對拍在第 101 條抓到的，靜態看程式碼看不出來。

## 7. packed 欄位

`LDP`(@0x0a77)、`STP`(@0x0a91)、`IXP`(@0x0a50)。三元組的次序是位址、位元數、
最右 bit 編號（`docs/10-interpreter/addressing.md`）。

原版用 `cs:1FB6h` 那張現成的遮罩表（第 n 項 ＝ `(1<<n)−1`）；
這裡直接算，結果相同。**這是 remake 自訂的實作手法，不是行為差異**——
那張表存在的理由是 8086 上算遮罩比查表貴，Go 沒有這個問題。

`IXP` 用一次除法同時得到「第幾個 word」與「word 內第幾格」（@0x0a50 的 `div bp`）。

## 8. 同段呼叫與返回

8.1 `CPL`(@0x1310)、`CPG`(@0x1337)、`CPI`(@0x1368)、`SCPI1`／`SCPI2` 共用
@0x101b → @0x103a → @0x1057。差別只在靜態鏈的來源：

| 指令 | 靜態鏈 |
|---|---|
| `CPL` | 呼叫者自己的 MP |
| `CPG` | `BASE`（＝ `Global − 8`）|
| `CPI`／`SCPIn` | 往外走 DB 層之後那一層的 MP |

8.2 字典項指的是 `DATASIZE`，第一條指令在它後面一個 word（spec 01 §5.4）。
`DATASIZE` 為負表示原生碼，這裡回錯誤。

8.3 配置區域資料：`SP −= 2 × DATASIZE`（@0x02da 算出來的值，
扣掉呼叫時壓在堆疊上的東西之後就是這個）。

8.4 MSCW 的推入順序（@0x1057）是 `MSPROC`、`MSENV`、`MSIPC`、`MSDYN`、`MSSTAT`。
堆疊往下長，所以從 MP 往上就是 Figure 5 的欄位順序，而區域變數從 `MP+10` 開始。
**順序錯了，被呼叫者的區域變數會蓋掉控制欄位。**

8.5 `RPU`(@0x1102) 把它拆回來：`SP = MP − 2`，依序取走 `[MP−2]`、`MSSTAT`、
`MSDYN`（成為新的 MP）、`MSIPC`、`MSENV`、`MSPROC`，最後 `SP += 參數位元組數`。
`MSCW` 的 `E_Rec` 與目前的不同時是跨段返回，還沒實作。

## 8bis. 跨段呼叫

8.6 `SCXG`(@0x0545)、`CXL`(@0x13b8)、`CXG`(@0x13eb／@0x1413)、`CXI`(@0x1457／@0x1475)
共用同一條路：**先切段，再照同段的方式建框**。
`SCXG n` 就是 `CXG`，段號編在 opcode 裡（`shr di,1; sub di,6Fh`）。

靜態鏈的來源：`CXL` 用呼叫者的 MP、`CXG`／`SCXG` 用**目標段**的 `BASE`
（@0x1420 的 `push word_30`，而 `word_30` 在切段時已經換成新的）、
`CXI` 往外走 DB 層。**要在切段之前算**——走鏈是呼叫端這一側的事。

8.7 切段是**一整組**：程式碼、`Env_Data`、程序字典、常數池、`E_Rec` 一起換。
少換一項不會報錯：常數池沒換就讀到別段的常數、字典沒換就呼叫到別段的程序，
兩者都只是安靜地讀到看起來像資料的東西。

8.8 `MSCW` 的 `MSENV` 要記**呼叫端**的 `E_Rec`。原版是 @0x1057 先推進去新的、
@0x10db 再改回舊的；直接推舊的效果一樣。記錯了返回時換不回來。

8.9 段不在記憶體時原版退回指令開頭發 segment fault，讓作業系統載入之後
**重跑同一條指令**（@0x143d 的 `si = ss:24h; dec si`）。
這裡回 `ErrNotResident`——載入是宿主的事。

8.10 **段 1 的程序可能是內嵌在宿主裡的原生碼**（手冊 p.66）。
原版的 `CXG` 在**切段之前**查那張表（@0x13f4），查到就直接跳進機器碼、
段完全不換。先切再發現會留下換了一半的狀態，而那不會報錯。

8.11 `RPU` 的 `MSCW` 裡 `E_Rec` 與目前的不同就是跨段返回，要先把段換回去
（@0x1102 的 `bp = [MP+6]; cmp bp, word_3E`）。

8.12 **`Environment` 這一層刻意不放進 p-machine。** 段號怎麼對到記憶體裡的
那一段，牽涉 `E_Vec`、`SIB` 與 Codepool——那是作業系統的資料結構，
換一個宿主就完全不同。p-machine 只問「給我那一段的樣子」。

實作端（`oracle/parity.go` 的 `liveEnv`）照 @0x0fba 的做法算：

```
段值 ＝ paragraph(Codepool 基底) ＋ (池內偏移 ÷ 16)
```

`Seg_Base` 是 `SIB` 開頭兩個 word：指向 Codepool 基底的指標（相對 `ss`）
與池內位元組偏移。細節與實測數據見 `docs/10-interpreter/segment-switching.md`。

## 9. 驗證

`oracle/conform_test.go` 的 `TestParityAgainstTheOriginal`：從原版此刻的狀態
展開，兩邊逐條走，每一條之後比 `IPC`、`SP`、`TOS`。
三項只要有一項對不上就停——繼續跑只會讓錯誤累積成看不懂的雜訊。

**停下來的三種情形分得出來**：走完、有指令還沒實作、真的對不上。
只有第三種是失敗；第二種是進度，它會準確指出下一支要做的是哪一個。

目前：**306 條逐條一致，用到 56 種 opcode，0 個分歧**，
停在段 1 的內嵌原生程序（不是跨段機制本身）。

跨段呼叫另外驗兩件事：

- `TestSegmentResolutionMatchesTheOriginal`：我們算出來的程式碼段內容、
  全域基底、程序字典、常數池、`E_Rec` **五項與原版切過去之後完全相同**。
  這一條特別重要，因為 `Seg_Base` 的換算法是量出來的，不是手冊寫的；
  量錯的症狀是「跳進另一段的中間」，不會報錯。
- `TestParityAcrossASegmentSwitch`：把原版推到下一條就是真換段的地方再展開，
  **逐條對拍實際走過那一次換段**（`E_Rec D7D2 → 0664`）。

測試同時釘住一個下限（`parityFloor`），確保進度不會倒退。

`internal/pmachine/pmachine_test.go` 另外用手寫的 p-code 釘住幾條容易錯的規則
（短形式的基底、`big` 要乘二、相對位移的起算點、條件跳躍只看最低位、
比較的運算元次序、packed 欄位來回一趟、MSCW 的版面），不需要原版素材。

## 10. 還沒做的

**段 1 的內嵌原生程序**是目前對拍停下來的地方。那 26 支是宿主的機器碼，
不是 p-code——要一支一支反組譯出語意。

浮點（16 支專屬常式）、集合、字串比較、多工（`SIGNAL`／`WAIT`）、
`CSP`、多字搬移（`MOV`／`STM`）都還沒有。
