# `SYSTEM.PME.86` 的前 36 個位元組

檔案開頭有 18 個非零的 word，後面一路是零到 `0x0100` 之後才開始出現程式碼。
這 18 個值不是指令。

```
偏移  0x00: 3a04 0000 0c9b 0000 00e6 0026 0028 003e
偏移  0x10: 02fe 185a 1865 1870 1874 0306 1281 11bc
偏移  0x20: 11ba 11af 0000 0000 …
```

## 已經能對上的三格

`0x0026`、`0x0028`、`0x003e` 這三個值，剛好就是直譯器三個狀態變數的 `ss:` 偏移：

| 值 | 是誰 |
|---|---|
| `0x0026` | 局部資料基底（`MP + 8`） |
| `0x0028` | 全域資料基底（`Env_Data + 8`） |
| `0x003e` | 目前的 `E_Rec` |

其餘十五個值全部落在 `0x02fe`–`0x3a04` 之間，也就是程式碼的範圍。

## 一個還沒證實的讀法

作業系統本體 `SYSTEM.PASCAL` 是 p-code 寫的，但它必須有辦法叫到直譯器的機器碼
（載入段、處理 segment fault、切換 task），也必須讀得到直譯器的狀態。
**一張放在檔案最前面、位置固定的位址表**是最直接的做法：
載入器把整份 PME 搬進記憶體之後，這張表就是它與 p-code 世界之間的介面。

「三個值恰好是狀態變數偏移、其餘是程式碼位址」支持這個讀法，
但沒有找到讀這張表的碼——讀它的是載入器，而載入器不在這個檔案裡。

手冊 p.17 提到一種叫 `InterpRel` 的重定位類型，也可能與這張表有關。
兩種讀法都沒有證據排除對方。

## 邊界

- 上面的位址對照是「值域比對」，不是追到使用端。**沒有任何本 repo 的結論
  建立在這張表的解讀上。**
- `0x3a04` 與 `0x0c9b` 這兩格與其他值的性質看起來不同（一個接近檔尾、
  一個落在錯誤處理與定址助手之間），沒有解。
