# `SYSTEM.PME.86` の先頭 512 バイト

[English](pme86-header.en.md) ｜ **日本語** ｜ [繁體中文](pme86-header.md)

ファイルのいちばん前は、規則性の無い定数の山に見える——非ゼロのワードが 18 個、
そのあとはずっとゼロ、`0x0100` を過ぎてから数個が散在し、それからようやくコードが始まる。
これらの値は命令ではない。

```
オフセット 0x00: 3a04 0000 0c9b 0000 00e6 0026 0028 003e
オフセット 0x10: 02fe 185a 1865 1870 1874 0306 1281 11bc
オフセット 0x20: 11ba 11af 0000 0000 …
```

結論から言う。**あれはインタプリタ自身の初期化データである。** ローダはファイル先頭の
512 バイトをそのまま**データ・セグメントの同じオフセット**へ運び、そのあと `0x1d56` から
始まるディスパッチ表をイメージ・オフセット 0 へ移して上書きする。だからコード・セグメント
では見えない——データ・セグメントの中でだけ生きており、システムが落ちるまで生き続ける。

> 関連：[インタプリタの状態](../10-interpreter/machine-state.ja.md)｜
> [命令フェッチとディスパッチ](../10-interpreter/dispatch-and-threading.ja.md)

## どうやって確かめたか

システムを走らせ、**最初の p-code が実行される瞬間**に、データ・セグメントの先頭
512 バイトとディスク上の 512 バイトをワード単位で比べる：

```
ファイル先頭 512 バイト中の非ゼロ 37 ワードは、37 個すべてがそのまま
データ・セグメントに移っている
```

一つも違わない。ゼロの部分は実行時状態のために空けられた枠で——`IPC`、`MP`、`E_Rec`
などが、bootstrap から制御が渡る前に埋められる。

例外はただ 1 枠。`0x06` はファイル上では 0、メモリ上では `0x0140`。これは bootstrap が
埋める起動パラメータ領域のアドレスである。

## 中身は何か

この 37 ワードは**インタプリタによる OS への自己紹介**であり、そこに初期値がいくつか
加わっている。OS 本体は p-code で書かれており、インタプリタの状態がどこにあるか、
インタプリタに仕事をさせたいときどこへ跳べばよいかを知る必要がある：

| オフセット | 何か |
|---|---|
| `0x08` | SYSCOM のアドレス（`0x00E6`） |
| `0x0A` | 状態領域における局所データ基底（`MP + 8`）のオフセット |
| `0x0C` | 大域データ基底（`Env_Data + 8`）のオフセット |
| `0x0E` | 現在の `E_Rec` のオフセット |
| `0x12`–`0x18` | 4 つのネイティブ・コールバックの入口（`185A`／`1865`／`1870`／`1874`） |
| `0x1A`–`0x22` | その他のインタプリタ・コードのアドレス |
| `0x44` | byte sex フラグの初期値（1 ＝ ホストと同じ） |
| `0xE6` 以降 | SYSCOM：デバイス数とパラメータ |
| `0x140` 以降 | 起動パラメータ、および最外枠の `MSSTAT`／`MSDYN` |
| `0x178`／`0x17A` | 大域変数 1、SYSCOM を指す |

4 つのコールバックはインタプリタ内でこうなっている（`0x185A` から）：

```
185a: mov bp, sp
185c: mov di, [bp+4]
185f: call 0x1791      ; SIGNAL
1862: lret 2
1865: mov bp, sp
1867: mov di, [bp+4]
186a: call 0x1878      ; 割り込み到来：そのベクタに繋がれたセマフォを SIGNAL
186d: lret 2
1870: call 0x1837      ; 割り込み禁止
1873: lret
1874: call 0x183c      ; 割り込み許可
1877: lret
```

`lret` は、これらが**far call 用**であることを示す——OS は p-code 側から `NAT` を
経由して入ってきて、`lret` で戻る。これがまさに「p-code の世界」と「機械語の世界」の
あいだの扉である。

## なぜこの方式なのか

**ファイルの先頭に位置が固定された**データなら、ローダは中身の枠を一つも認識せずに、
何も考えずに運ぶだけでよい。インタプリタのバージョンが変わっても、変わるのは自分の表だけで、
ローダは動かさなくてよい。

その 512 バイトをディスパッチ表と共有しているのも偶然ではない。
**ロード後、その空間はコード・セグメントにとって無用**である（表は
`jmp word ptr cs:[di]` にディスプレイスメントを持たせないため、オフセット 0 へ移す必要がある）。
だからそこに「複製して外へ出したいデータ」を置く。1 バイトも無駄にならない。

## 境界

- `0x3a04` と `0x0c9b` の 2 枠は未解。値域から見ると片方はファイル末尾に近く、
  もう片方はエラー処理とアドレッシング・ヘルパのあいだに落ちるが、使用側までは追えていない。
- `0x12` 以降のアドレスは**この 1 本のインタプリタのもの**である。再実装機に対応物は無い——
  OS が必要とするのは `NAT` 呼び出しのときだけで、`NAT` には実物の 8086 が要る。
- 「37 ワードすべて一致」は実測（`TestInterpreterDataComesFromItsOwnHeader`）。
  「ゆえに初期化データである」はその実測に対する最も素直な読み方である。
