# Parhelion PME

[English](README.en.md) ｜ **日本語** ｜ [繁體中文](README.md)

幻日 —— Go で作り直した UCSD p-System と、それを支える知識ベース。

1984 年の `.VOL` ディスクイメージを 1 枚渡すと、p-System が自力でコマンド
ラインまで起動し、キー入力に反応し、Filer がディレクトリを一覧する。
**オリジナルのインタプリタも DOS も 8086 エミュレータも使っていない。**

<p align="center"><img src="img/boot-screen.svg" width="820" alt=".VOL を 1 枚渡すと p-System が自力で起動する"></p>

`--->` の 5 行は、オペレーティングシステムが**自分で**システムファイルを
RAM ディスクへコピーしているところ。打てば動く：

<p align="center"><img src="img/filer-screen.svg" width="820" alt="F で Filer、L でディレクトリ一覧"></p>

この 5 つのファイルは**起動時に OS 自身が** RAM ディスクへ置いたもの。

## いま何ができるか

| | |
|---|---|
| p-code の実行 | **210 命令すべて**。浮動小数点・集合・packed フィールド・文字列を含む |
| セグメント間の呼び出しと復帰 | 呼び出し 9 系統、`EXIT` による枠の巻き戻し（EXITIC）、activity と参照カウント |
| マルチタスク | セマフォ、ready queue、優先度によるタスク切り替え |
| セグメントのロード | メモリにないセグメントは segment fault を上げ、OS のローダタスクを起こす |
| ディスク | `.VOL` イメージの読み書き、ディレクトリ解析、RAM ディスク |
| コンソール | 80×25 の端末エミュレーション（カーソル位置指定、行消去、画面消去、スクロール）。キーがなければ制御を返し、文字を足せば同じ命令から再開する |
| デバイス構成 | `SYSTEM.CONFIG` を解析。unit 番号とドライバは設定ファイルが決める |
| 起動 | OS の先頭セグメントをディスクから読み込み、SIB・E_Rec・E_Vec・TIB・最外側の活性化レコードを組み立てる |

現在動くもの：p-System の **Startup Utility** と **Filer**
（ディレクトリ一覧、ボリューム切り替え）。

## 境界はどこか

境界はこちらが引いたものではない。インタプリタ自身が 48 個のテーブル
（イメージの `0x1F56`）を持っていて、「これは p-code ではなくホストの機械語だ」
と宣言している。

| 側 | 担当 | 状況 |
|---|---|---|
| 210 個の p-code 命令 | `internal/pmachine` | すべて |
| セグメント 1 の組み込みネイティブ手続き | `internal/psystem` | 相異なる 26 本のうち 21 本 |
| ディスク・コンソール・時計・RAM ディスク | `internal/psystem` | 起動と Filer に必要なものは揃っている |
| `NAT`（コードセグメント内の 8086 機械語） | — | **構造的に不可能**。8086 が要る |

未実装のネイティブ手続き：`31`／`33`（デバイスモード 3）、`32`、`37`、
`47`（別の浮動小数点ルーチン群に差し替える——`0x1F56` のテーブル自身を
書き換える）。起動にはどれも要らない。

**unit 128 は DOS ホストのファイルシステムゲートウェイ**で、p-System から
下の DOS のファイルを読み書きするためのもの。Go ホストの下に DOS はないので
答えは常に「何もない」——`NAT` と同じ種類の境界であって、やり残しではない。
やり取りの形は実測して [spec 03](docs/30-remake/specs/03-boot.ja.md) に書いてある。

データセグメント下位のブロックの出所も判明した：**あれはインタプリタ自身の
初期化データ**で、`SYSTEM.PME.86` の先頭 512 バイトがそのまま同じオフセットへ
コピーされている（非ゼロの 37 ワードが 1 つも違わない）。中身はインタプリタが
OS に対して行う自己紹介（SYSCOM の位置、いくつかの状態オフセット、
4 つのネイティブコールバック入口）。**ブートストラップが自分で計算しているのは
4 か所だけ**：起動パラメータ領域のアドレス、データセグメントの物理アドレス、
そしてタスクのスタック上下限。

## 正しいとどう確かめたか

指標は 4 つ、それぞれ別のことを問う。**最初の 2 つはオリジナルを必要としない**：

| テスト | 問い | 現在 |
|---|---|---|
| `TestBootReachesTheCommandLine` | 起動したか | コマンドラインまで到達し、キー待ちで停止 |
| `TestFilerListsTheRAMDisk` | 使えるか | `F` → `L` → 画面の正しい位置に 5 ファイル |
| `TestSelfBootMatchesTheOriginal` | p-code は同じか | **226,623 命令**、起動全体 |
| `TestSelfBootInitialStateDiff` | 起動時の状態は正しく組めたか | 409 か所が相違、うち 397 はホストの機械語 |

後ろの 2 つはオリジナルを横に並べて 1 命令ずつ突き合わせる——それがこの
プロジェクトの方法であり、名前の由来でもある。さらに**共走**もある：
オリジナルが駆動し、こちらが追随して、毎命令 `IPC`・`SP`・`TOS`・`E_Rec` の
4 項目を比べる。

```
$ tools/go.sh run -tags oracle ./cmd/parity -pme .../SYSTEM.PME.86
両者一致で 224999 命令を実行
別に 1624 命令はオリジナルに任せた（ホストの仕事、**未検証**）： 70 SCXG1x1617 94 CXGx7
停止した理由： オリジナルがもう p-code を実行していない（入力待ちループ）

使われた opcode 173 種：…
```

任せた 1,624 命令は、p-machine が定義上そもそも手放す 2 種類だけ：
セグメント 1 の組み込みネイティブ手続きと、まだメモリにないセグメント。
**未実装の p-code 命令は含めない**——それを許すと「まだやっていない」が
「できている」に見えてしまう。

### 起動経路が通らない命令

起動で使われる opcode は 173 種にとどまり、浮動小数点 16 命令には一度も
触れない。OS の起動に実数は出てこないからだ。そこは**単一命令の共走**で
検証する：命令バイトとオペランドをこちらが指定し、オリジナルのコード
セグメントとスタックへ書き込み、両者を 1 命令ずつ進めてワード単位で比べる。

```
ADR = 4.75      MPR = 1.0000000000000001e-305     DVR = 0.3333333333333333
MODI(-17,3) = 1        RND(-3.5) = -4        LESTR("AB","ABC") = 1
```

55 例すべて一致。これで**共走のカバー率は 211 種中 205 種**になった。
残る 6 種：`CPI`／`CXL`／`CPF`（本当に別の手続きへ飛ぶ）、
`BPT`（意図的に実行時エラーを起こす）、`NAT`（構造的に不可能）、
`LDCRL`（オペランドが定数プールを指すため、そこへ値を置くと壊れる）。

### 共走が言っていないこと

比べているのはスカラー 4 つで、スタック全体ではない。
**スタックの奥を壊しても、その後誰も読まなければ**気づけない。

独立した裏取りが 1 つ副産物で得られた：Filer が表示した日付
`2-Sep-90`・`14-Jan-85`・`20-Dec-84` は、ディスク上の `daccess` フィールド
（`B429`・`AAE1`・`A94C`）を自前のデコーダで解いた結果と 1 つずつ一致する。
**独立した 2 つの読み手が同じ答えを出した。**

## 名前について

話は 1985 年の Atari ST のゲームから始まる。**SunDog: Frozen Legacy** の
ゲームロジックは 68000 の機械語ではなく p-code で、それを解析したことが
すべての出発点だった。

**sun dog の正式名称は parhelion（幻日）**——大気中の氷晶が陽光を屈折させ、
本物の太陽から 22 度離れた位置に第二の太陽をつくる現象。太陽ではないのに
見間違えるほど明るく、しかも**本物の太陽が出ているときにしか現れない**。

エミュレータとはまさにそれだ。見間違えるほど本物に似た像であり、その正しさは
本物によってしか定義できない。このプロジェクトの検証はまさに二つの太陽を
並べること——同じ codefile をオリジナルと Go 版に食わせ、出力が一致すること。

`PME` はオリジナル自身のファイル名（`SYSTEM.PME.86`、P-Machine Emulator）から。
`86` は 8086。名前は出発点を記念しているが、**題材は 1984 年 DOS 版の 8086
インタプリタであって、SunDog の 68000 版ではない。**

## 動かし方

`tools/go.sh` が Go を docker で包み、`tools/ci.sh` がローカル CI。
外部素材が要る検査は自分でスキップし、**スキップしたと明示する**。

```sh
tools/ci.sh                                   # 素材の要らない分だけ

PARHELION_CODEFILE=/src/workplace/SYSTEM.PASCAL \
PARHELION_ORIG=~/cht/p-code/psys21/"psystem 1984" \
PARHELION_PME=/src/workplace/SYSTEM.PME.86 \
PARHELION_DOSGOLEM=~/cht/dosgolem-psys \
  tools/ci.sh                                 # 全部
```

オリジナル素材（`.VOL`、`PSYSTEM.COM`、抽出した `SYSTEM.PME.86`）は各自で
用意する。無ければスキップ——**代用品は作らない**。黙って差し替えると
「まだ検証していない」が「検証済み」に見えてしまう。

| コマンド | 何をするか |
|---|---|
| `cmd/boot` | `.VOL` を 1 枚受け取って p-System を起動する |
| `cmd/parhelion` | codefile を読む：セグメント辞書、ルーチン表、バイト順 |
| `cmd/pcode` | p-code を逆アセンブルする |
| `cmd/parity` | 共走（`-tags oracle` が要る）|
| `cmd/bootdump`／`cmd/whowrote`／`cmd/ioprobe`／`cmd/hostprobe`／`cmd/segprobe` | オリジナルの実挙動を測るプローブ（`-tags oracle`）|

共走の下にあるのは [`dosgolem`](https://github.com/wicanr2/dosgolem)——同じ作者に
よるヘッドレス決定論的 DOS 実行器。`oracle/` の層が p-machine を知っていて
（インタプリタの位置特定、dispatch 先の判定、p-code トレースの読み取り）、
dosgolem は汎用の機能だけを提供する。**実際に動く側はそれを import しない**：
オリジナルはテストの中にしか現れない。

## 出典

**SofTech『UCSD p-System and UCSD Pascal Version IV.0 Internal Architecture
Guide』**（1981）。節ごとの要約は
[`ucsd-pascal-notes`](https://github.com/wicanr2/ucsd-pascal-notes) の
`docs/50-iv-internals/` にあり、スキャンも同じリポジトリにある。

実測対象は `psys21`（1984 年の DOS ホスト版 p-System）ディスクイメージ内の
`SYSTEM.PME.86`、sha256 `fe427aa66ca8…`。**本リポジトリにオリジナルの
ディスクイメージや実行ファイルは含まれない**。バイトレベルの結論と
逆アセンブル出力だけを置いている。

p-machine の一般則、命令エンコーディング、手続き呼び出しの第一原理からの
導出は [`ucsd-pascal-notes`](https://github.com/wicanr2/ucsd-pascal-notes) に。
本リポジトリは 8086 版の実装と作り直しを扱う。

## 限界

- 「IV.2.1」というバージョンはディスクの配布表示によるもので、
  **ファイル自体からバージョン番号を読んだわけではない**。
- ニーモニックは IV.0 マニュアルの付録から。番号は 1 マスずつ照合済みだが、
  命令ごとの意味が同一であることは検証していない。
- 169 本すべてを逆アセンブルしたが、**全部を読んだわけではない**。
  読んで文書化したのは約 30 本、残りは表レベルの統計のみ。
- 逆アセンブルは最初の無条件分岐で打ち切るため、各ルーチンは主経路だけを
  カバーする。飛んだ先は別途追う必要がある。
- 起動が通るのは**このディスク、この構成**での経路。別のディスクや別の構成は
  まだ検証していない道へ入る。
